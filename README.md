# Староста · О-26-ИСТ-сии-Б

Рекомендуемый запуск: **GitHub Pages + Supabase Free**. Отдельный сервер не нужен.

## Возможности

Без ключа доступно расписание; после входа — общий журнал группы, посещаемость, сдачи и сборы. Два независимых ключа проверяются в базе. Автосохранение и проверка изменений другого устройства каждые 15 секунд. Конфликт версий не затирает чужую работу: сначала скачайте черновик, затем загрузите облачную версию и перенесите нужные изменения вручную.

Формы работают внутри страницы. Кнопки и длинные названия переносятся на маленьких экранах. PWA получает свежую версию через сеть, при отсутствии сети показывает ранее сохранённую оболочку и расписание. Для нового входа в журнал нужен интернет.

## Подключение без сервера

1. Создай проект на https://supabase.com/dashboard — достаточно тарифа Free. Пароль базы сохрани у себя: приложению он не нужен.
2. Открой SQL Editor, вставь `supabase.sql` и выполни. В Results появятся два ключа: староста и заместитель. Сохрани оба, заместителю передай только её ключ. Не добавляй их в GitHub или config.js.
3. В настройках Supabase найди Project URL и публичный Publishable key (или legacy anon key). Заполни в `config.js`:

```js
window.STAROSTA_SUPABASE_URL = 'https://PROJECT.supabase.co';
window.STAROSTA_SUPABASE_KEY = 'ПУБЛИЧНЫЙ_PUBLISHABLE_ИЛИ_ANON_KEY';
```

Публичный API-ключ предназначен для браузера. Не вставляй `service_role`, secret key или пароль базы.

4. Загрузи файлы в `main`. В GitHub **Settings → Pages → Source** выбери **GitHub Actions**. Запусти workflow **Publish site and refresh BGTU schedule**. Он публикует только файлы сайта.
5. Открой https://crown350.github.io/for-starosta/ и войди по ключу. Если в старой версии уже были данные, используй тот же браузер: **Управление журналом → Перенести данные с этого устройства**. Это явная замена общего журнала, предназначенная для первого переноса или осознанного восстановления.

Поля Supabase сейчас пустые: реальный облачный проект ещё не подключён. Проверка SQL локально не заменяет проверку после подключения проекта.

## Расписание

Источник: https://www.tu-bryansk.ru/education/schedule/?form=%D0%BE%D1%87%D0%BD%D0%B0%D1%8F

Загрузчик Yandex Cloud Functions `bgtu-sync` подготовлен в `yandex/bgtu-sync/`: установка и почасовой таймер описаны в его README . Supabase хранит снимок; приложение читает его автоматически при открытии и входе в журнал. Кнопка «Обновить расписание» обращается напрямую к Yandex; общий кэш в БД ограничивает запросы до одного в минуту. Строка «Обновлено» показывает fetched_at, после 6 часов снимок выделяется. При недоступности Edge молча используется schedule.json. В CSP connect-src добавлен только https://functions.yandexcloud.net.

Снимок меньше 10 занятий не записывается. Хеш проверяется в Node.js и атомарно в БД: одинаковые JSON/changed_at остаются прежними, fetched_at отражает последнюю успешную проверку. HTTP-запрос ограничен 20 секундами, предусмотрены два повтора временных ошибок. Ключ Supabase задаётся только в окружении Yandex.

Обновление расписания выполняет Yandex bgtu-sync: почасовой триггер bgtu-hourly и кнопка в приложении. GitHub Actions только публикует Pages; загрузка БГТУ и cron отключены после подтверждения автозапуска.

Загрузчик использует текущий выбранный период официального сайта. В реальной таблице `schname` — предмет, `schclass` — аудитория. Пустые строки учитываются при определении верхней/нижней недели. Чётность вычисляется для выбранной даты. Прошедшие занятия и записи с отметками не удаляются при обновлении. Разовые переносы и праздники нужно сверять с БГТУ: источник содержит недельный шаблон.

## Ключи и резервные копии

Ключ входа хранится только в памяти вкладки. В базе находятся SHA-256 хеши случайных ключей. Таблицы закрыты от публичного API; функция проверяет ключ и версию записи. Для отзыва ключа заместителя выполни в SQL Editor:

```sql
update starosta_private.keys set active=false where label='заместитель';
```

Последний блок `supabase.sql` генерирует новые ключи обоим редакторам без удаления журнала. Скопируй новые значения из Results. Периодически скачивай резервную копию в «Ещё». Бесплатный тариф имеет ограничения и может приостанавливать неактивные проекты: https://supabase.com/pricing

При конфликте сначала скачай несохранённое, затем загрузи из облака. Автоматического объединения нет. Черновик последней правки сохраняется на устройстве и доступен кнопкой «Скачать черновик устройства» после входа.

## Локальная проверка / дополнительный Node.js сервер

Node.js 22+, зависимости приложения не нужны:

```sh
npm test
npm start
```

Сайт: http://127.0.0.1:8787 — расписание из `schedule.json` доступно сразу. Для тестирования журнала через Node задай `OWNER_KEY` и `DEPUTY_KEY`: случайные строки минимум 32 символа. `DATA_DIR` — постоянная папка журнала; `ALLOWED_ORIGIN` — разрешённый источник GitHub Pages. Нужен один процесс Node, без нескольких реплик. Запись атомарная; предыдущая версия — `state.json.bak`. Временный диск хостинга для этого режима не подходит.

Для прямой загрузки расписания через Node установи `STAROSTA_STATIC_SCHEDULE=false`. При отдельном сервере задай его HTTPS-адрес в `STAROSTA_API`. В рекомендуемом варианте Supabase менять эти поля не нужно.
