# Обновление bgtu-sync для публичного вызова

1. Откройте в Yandex Cloud существующую функцию bgtu-sync, ID d4eaviacehbf42ii18hm → Редактор. Загрузите bgtu-sync-public.zip целиком. Точка входа index.handler; Node.js 22; память 128 МБ; таймаут 360 секунд.
2. Сохраните существующие SUPABASE_URL и SUPABASE_SERVICE_ROLE_KEY в переменных окружения. Секретов в ZIP нет. Сохраните новую версию с тегом $latest. Публичный доступ уже проверен HTTP 200; оставьте его включённым.
3. Вызовите https://functions.yandexcloud.net/d4eaviacehbf42ii18hm . Новая версия возвращает массив lessons (25 элементов), cached, changed, fetchedAt и last_attempt_at. Повторный вызов в течение 60 секунд должен вернуть cached:true без обращения к БГТУ.
4. Проверьте существующий bgtu-hourly: активен, cron 0 * ? * * *, функция bgtu-sync, тег $latest, сервисный аккаунт с ролью functions.functionInvoker. Не создавайте второй триггер.
5. После часового запуска найдите в логах origin:timer, triggerId и last_attempt_at. Ручной HTTP-вызов имеет origin:http. Передайте запись автозапуска для сравнения с БД; ручной тест не доказывает работу таймера.
6. После загрузки новой версии сообщите об этом: интерфейс с прямой кнопкой подготовлен локально, его можно публиковать и проверять после обновления функции.

Ограничение общее: единственная строка starosta_private.schedule_cache с id=1. SQL атомарно выдаёт право на запрос; два устройства используют один кэш. last_attempt_at обновляется при получении права на реальную проверку. Пока запрос выполняется, блокировка сохраняется до завершения или до 7 минут после аварии. Успешный повтор в пределах 60 секунд не обращается к БГТУ.

CORS разрешает Origin https://crown350.github.io, методы GET/POST/OPTIONS. Ключ редактора не нужен. Supabase RPC доступны только service_role. HTTP-ошибка возвращается с CORS и не затирает снимок. Ошибка таймера также отмечается ошибкой выполнения.

Снимок меньше 10 занятий отклоняется. При одинаковом хеше JSON и changed_at сохраняются, fetched_at отражает успешную проверку. Время не подменяется при ответе из кэша.

GitHub Actions пока не изменён: его отключение требует отдельного подтверждения после успешного запуска Yandex и обновления даты в приложении.
