# bgtu-sync: установка в Yandex Cloud (8 шагов)

1. В каталоге Yandex Cloud откройте **Cloud Functions → Создать функцию**, имя `bgtu-sync`. Оставьте функцию **приватной**.
2. **Редактор**: среда `Node.js 22`, источник **ZIP-архив**, файл `bgtu-sync.zip`; точка входа `index.handler`, память **128 МБ**, таймаут функции **360 секунд**, сервисный аккаунт функции **Не выбран**. 360 секунд покрывают пять HTTP-запросов с лимитом 20 секунд и двумя повторами каждого; обычно выполнение намного быстрее.
3. **Переменные окружения**: `SUPABASE_URL=https://piwxslgxwmdrehnomymt.supabase.co`; `SUPABASE_SERVICE_ROLE_KEY=<серверный ключ проекта>`. Возьмите `service_role` во вкладке Legacy API Keys проекта Supabase, либо отдельный `sb_secret_…` в API Keys. Publishable/anon и ключи редакторов здесь не подходят. Секрет вставьте только в окружение функции, не в ZIP или репозиторий. **Сохранить изменения**.
4. **Тестирование**: тег `$latest`, шаблон **Без шаблона**, данные `{}` → **Запустить тестирование**. В `body` ожидаются `ok:true`, `lessons:25` (либо другое число не меньше 10), `fetchedAt`; `changed:false` допустимо. При ошибке откройте **Логи**: функция завершается ошибкой, старый снимок сохраняется.
5. В каталоге **Сервисные аккаунты → Создать сервисный аккаунт**: имя `bgtu-timer`, роль на каталог **`functions.functionInvoker`**.
6. **Cloud Functions → Триггеры → Создать триггер**: имя `bgtu-hourly`, тип **Таймер**, тип приёмника **Функция**, cron **`0 * ? * * *`** — каждый час в :00 UTC (также :00 МСК), данные `{}`.
7. **Настройки функции** триггера: функция `bgtu-sync`, тег `$latest`, сервисный аккаунт `bgtu-timer`. Повторные вызовы триггера: количество **1**, интервал **60 секунд** (это отдельно от двух повторов HTTP внутри функции). Создайте триггер, убедитесь, что он активен.
8. Перезагрузите https://crown350.github.io/for-starosta/ и откройте **Ещё → Расписание БГТУ**. Пришлите `body` успешного вызова и значение **«Обновлено»** из приложения. Только после этого подтверждения будет отключено обновление БГТУ в GitHub Actions; пока оно сохранено.

## Поведение

- Только встроенные модули Node.js: HTTPS, crypto, zlib; npm install не нужен.
- GET с PHPSESSID → POST group → POST schedule. Учебный период берётся из выбранного пункта сайта; при неизвестном периоде запись отклоняется.
- Каждый HTTP-запрос: общий лимит 20 секунд на соединение и чтение; максимум 3 попытки (исходная + 2 повтора) при сетевых/временных HTTP-ошибках.
- Некорректная разметка или меньше 10 занятий — ошибка до обращения к записи Supabase. Порог продублирован в БД.
- SHA-256 сравнивается в функции; БД атомарно перепроверяет свой хеш под блокировкой. JSON и changed_at сохраняются при равенстве, fetched_at обновляется после успешной проверки. Это время получения, а не время изменения содержания.
- Параллельный или повторный запуск не перезаписывает более свежий снимок старым.
- Функция принимает только фиксированный источник БГТУ и фиксированную группу, входной event не задаёт URL/SQL.
- Интерфейс автоматически читает снимок при открытии и входе в журнал. При сбое Edge использует schedule.json без уведомления; снимок старше 6 часов выделяется.
